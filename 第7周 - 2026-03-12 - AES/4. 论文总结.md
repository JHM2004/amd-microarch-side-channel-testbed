这篇论文《Cache Misses and the Recovery of the Full AES 256 Key》提出了一种基于**缓存缺失**的新型侧信道攻击方法，能够高效地从AES的T表实现中恢复密钥，尤其针对AES-256。与传统基于缓存访问的攻击不同，作者利用**缓存行未被访问**的事实来丢弃错误的密钥候选值，从而大幅减少所需样本数（93%~98%），并在毫秒级时间内恢复完整密钥。

## 核心思想
- **传统攻击**：关注缓存命中（access），但命中可能发生在多个轮次，引入噪声。
- **本文方法**：关注缓存缺失（miss），即某缓存行在整个加密过程中从未被访问。这能确定性地丢弃对应密钥候选，因为若某行未被使用，则所有会导致访问该行的输入值都不可能发生。
- **优势**：信息更纯净，样本需求大幅降低，且可扩展到AES-256。

## 攻击目标与假设
- **目标**：OpenSSL中基于T表的AES实现（1.0.1f及以后，编译时带`no-asm`标志）。
- **假设**：
  1. 攻击者与受害者共享CPU缓存（如云环境中的同主机不同VM）。
  2. 攻击者能监控特定缓存行是否被访问（通过Flush+Reload、Prime+Probe等技术）。
  3. 攻击者能获取每次加密的密文（或明文，但本文假设已知密文）。

## AES T表实现回顾
- 加密使用四个`Te`表（`Te0`~`Te3`），每个表256个32-bit项（1024字节），缓存行64字节 ⇒ 每行含16个表项。
- 每个`Te_i`表项对应一个输入字节`x`，存储32位值，其中四个字节分别对应MixColumns后对四个输出行的贡献。
- 最后一轮无MixColumns，直接使用S盒输出（隐含在`Te`表的特定字节中）。
- 解密使用`Td`表，结构类似。

## 攻击AES-128（算法2）
### 监控目标
- 选择每个`Te_i`表的某个固定缓存行（例如索引0~15的行），记录每次加密中该行是否被访问（`X_i[t]=0`表示未访问）。

### 密钥恢复（最后一轮）
- **关系**：最后一轮输出字节`C[i][j]`（密文）与密钥`K[i][j]`、输入字节`S^{Nr}_{i, j+i}`的关系为：
  ```
  C[i][j] = K[i][j] ⊕ Te_{i+2}[ S^{Nr}_{i, j+i} ] 的对应行字节
  ```
  其中`Te_{i+2}[x]`的对应行字节即S盒输出。
- **映射**：监控`Te_i` ⇒ 影响的行`r = (i-2) mod 4`：
  - Te0 → 行2
  - Te1 → 行3
  - Te2 → 行0
  - Te3 → 行1
- **投票**：对每个未访问样本，遍历缓存行中16个索引`idx`，获取`Te_i[idx]`中行`r`的字节`v`，对于所有列`j`，丢弃候选密钥：
  ```
  candidate = C[r][j] ⊕ v
  count[r][j][candidate] += 1
  ```
- **结果**：每个密钥字节取计数最小的候选（正确密钥极少被丢弃）。

### 算法2伪代码
```
输入：X[0..3][t]（访问标志），C[t][4][4]（密文），Te表
输出：K_last[4][4]
初始化 count[4][4][256] = 0
for each encryption t:
    for i in 0..3:
        if X[i][t] == 0:
            r = (i-2) mod 4
            for offset in 0..15:
                idx = base_i + offset
                v = get_byte(Te_i[idx], r)  // 提取第r字节
                for j in 0..3:
                    cand = C[t][r][j] ⊕ v
                    count[r][j][cand] += 1
for each r,j:
    K_last[r][j] = argmin(count[r][j])
```

## 攻击AES-256（加密-解密攻击，EBD）
### 思路
1. 先用算法2恢复最后一轮（第14轮）密钥`K14`。
2. 利用解密等价算法，将未访问信息转换为对**解密第一轮密钥`Kd1`**的约束，从而得到第13轮加密密钥（两者通过`InvMixColumns`关联）。
3. 获得两个连续轮密钥后，通过密钥扩展恢复主密钥。

### 算法3：恢复解密第一轮密钥`Kd1`
- **已知**：密文`C`，`Kd0 = K14`，未访问标志`X_i`。
- **步骤**（对每个未访问样本）：
  1. 计算`D1 = C ⊕ Kd0`（按字节异或）。
  2. 对每列`j`，计算中间值`IV_j`（32位）：
     ```
     IV_j = Td0[ D1[0][j] ] ⊕ Td1[ D1[1][(j-1) mod 4] ] ⊕ Td2[ D1[2][(j-2) mod 4] ] ⊕ Td3[ D1[3][(j-3) mod 4] ]
     ```
  3. 提取`IV_j`中对应行`r`的字节`iv_byte`（`r`由监控的`Te_i`决定）。
  4. 对缓存行中每个索引`idx`，取`Te_i[idx]`中行`r`的字节`v`（即S盒输出），丢弃候选：
     ```
     cand = iv_byte ⊕ v
     countKd[r][j][cand] += 1
     ```
- 最终`Kd1[r][j] = argmin(countKd[r][j])`。

### 算法3伪代码
```
输入：X[0..3][t]，C[t]，Kd0，Te表，Td表
输出：Kd1[4][4]
初始化 countKd[4][4][256] = 0
for each encryption t:
    for i in 0..3:
        if X[i][t] == 0:
            r = (i-2) mod 4
            D1 = C[t] ⊕ Kd0
            for j in 0..3:
                IV = Td0[D1[0][j]] ⊕ Td1[D1[1][(j-1)&3]] ⊕ Td2[D1[2][(j-2)&3]] ⊕ Td3[D1[3][(j-3)&3]]
                iv_byte = (IV >> (8*(3-r))) & 0xFF
                for offset in 0..15:
                    idx = base_i + offset
                    v = get_byte(Te_i[idx], r)
                    cand = iv_byte ⊕ v
                    countKd[r][j][cand] += 1
for each r,j:
    Kd1[r][j] = argmin(countKd[r][j])
```

## 实现注意事项
1. **表数据**：需使用与OpenSSL一致的`Te`和`Td`表（可从OpenSSL源码中获取或模拟生成）。
2. **字节提取**：注意字节序，通常32位值中最高位对应行0，最低位对应行3。
3. **监控行选择**：通常选每个表的第一个缓存行（索引0~15），`base_i = 0`。
4. **样本数**：AES-128约3000，AES-256约8000（非虚拟化），虚拟化环境需更多。
5. **密钥扩展**：得到`K14`和`Kd1`后，需根据AES-256密钥扩展算法逆向计算主密钥。`Kd1`经`InvMixColumns`可得加密第13轮密钥`K13`，然后利用密钥扩展关系（如`K13`与`K14`的关系）恢复主密钥。

## 验证与测试
- 可先模拟AES加密，并模拟缓存访问记录（即跟踪每次加密中目标缓存行是否被使用）。
- 运行算法2和3，检查恢复的密钥是否与原始密钥一致。
- 可调整样本数，观察成功率与样本数的关系，验证论文中的改进比例。

## 总结
论文通过创新地利用缓存缺失信息，显著提升了缓存侧信道攻击的效率，并首次实现了对AES-256的完整密钥恢复（仅需约3倍于AES-128的样本）。复现时需仔细处理表映射和字节提取，并注意解密中间值的正确计算。
