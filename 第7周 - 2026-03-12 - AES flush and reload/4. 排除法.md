1. 背景
AES 最后一轮加密中，每个密钥字节 K 和对应的密文字节 C 满足：
C = S(x) ⊕ K，其中 x 是某个字节（0~255）。
S(x) 是把 x 代入 S 盒得到的结果。
攻击者不知道 x，但能监控 T 表的某个缓存行（比如 Te0 的前 16 个值，对应 x=0~15）。

---

2. 关键现象
如果某次加密后，攻击者发现 Te0 的那个缓存行 没有被访问（即缓存未命中），那就说明：
在这次加密中，x 绝对不在 0~15 之间。

---

3. 排除过程

· 如果 x 不在 0~15，那么 S(x) 就不等于 S(0)、S(1)……S(15)。
· 而 K = C ⊕ S(x)，所以 K 也不可能等于 C ⊕ S(0)、C ⊕ S(1) …… C ⊕ S(15)。
· 于是，我们就把这 16 个可能的 K 值 “排除” 掉（给它们各记一次“坏”）。

---

4. 统计
做很多次加密，每次如果有缓存未命中，就对相关的字节排除 16 个候选值。
正确的 K 值因为很少被排除（只有当 x 落在 0~15 时才会被命中，但这种情况很少），所以它的“坏”次数最少。
最后，每个字节选“坏”次数最少的候选，就是正确的密钥。

---

一句话总结：缓存未命中告诉你“某些输入值不可能”，因此它们推导出的密钥值也不可能，把这些不可能的值排除掉，剩下的就是正确答案。

## 答疑解惑（1）：

## 1. 数据结构

我们需要为 **16 个密钥字节**（0~15）分别维护一个大小为 **256** 的计数器数组。  
例如，用 `CK[pos][k]` 表示第 `pos` 个密钥字节的候选值 `k` 被排除的次数。  
初始所有 `CK[pos][k] = 0`。

---

## 2. 一次加密中四个 T 表的独立影响

在一次加密中，攻击者会监控 **四个 T 表**（Te0, Te1, Te2, Te3）的同一缓存行（比如每个表的前 16 个条目）。  
加密后得到四个标志 `X0, X1, X2, X3`，每个为 0 表示该表缓存行未命中（未被访问）。

四个表是**独立**的，因此一次加密中可能同时有多个表未命中。每个表负责影响 **特定行** 的四个密钥字节：

| 表   | 负责的行 | 影响的密钥字节索引（pos） |
| ---- | -------- | ------------------------- |
| Te0  | 行 0     | 0, 1, 2, 3                |
| Te1  | 行 1     | 4, 5, 6, 7                |
| Te2  | 行 2     | 8, 9, 10, 11              |
| Te3  | 行 3     | 12, 13, 14, 15            |

---

## 3. 一次未命中如何排除 16 个候选值？

当某个表（例如 Te0）未命中时，我们对该表负责的 **四个字节**（pos = 0,1,2,3）分别进行以下操作：

- 对每个字节 `pos`，取本次加密中该字节对应的密文值 `c[pos]`。
- 遍历缓存行中的 16 个索引 `l = 0..15`，计算 `s = sbox[l]`。
- 对于每个 `l`，得到一个候选密钥值 `candidate = c[pos] ⊕ s`。
- 将计数器 `CK[pos][candidate]` 增加 1（表示该候选值被排除一次）。

**注意**：  
- 每个字节独立计算，使用的密文不同，因此排除的 16 个候选值也不同。  
- 一次 Te0 未命中，会对字节 0 的 16 个候选、字节 1 的 16 个候选……各加 1，总共增加 4×16 = 64 次计数，但分布在四个不同的计数器数组上。

---

## 4. 为什么能恢复正确的密钥？

- 正确的密钥字节 `K_true` 只有在 **真实输入 x 恰好等于某个被监控的 l** 时，才会被访问（缓存命中），因此不会出现在未命中的样本中。  
- 在未命中的样本中，`x` 不在 0~15，所以 `K_true` 永远不会被排除，其计数器 `CK[pos][K_true]` 保持为 0（或非常小，但理论上应为 0）。
- 其他错误候选值会在各种未命中样本中被反复排除，计数器远大于 0。

经过足够多的样本，每个字节选择计数器最小的候选值，即为正确的密钥字节。

---

## 5. 举例说明

假设一次加密中：
- Te0 未命中（X0=0），Te1 命中（X1=1），Te2 未命中（X2=0），Te3 命中（X3=1）。
- 密文第一行（行0）字节为：c0=0x12, c1=0x34, c2=0x56, c3=0x78。
- 第二行（行1）字节为：c4=0x9A, c5=0xBC, c6=0xDE, c7=0xF0。
- 第三行（行2）字节为：c8=0x11, c9=0x22, c10=0x33, c11=0x44。
- 第四行（行3）字节为：c12=0x55, c13=0x66, c14=0x77, c15=0x88。

那么：
- 对 Te0（行0）：影响字节 0~3。  
  字节0：对 l=0..15，计算 candidate = 0x12 ⊕ sbox[l]，增加 CK[0][candidate]。  
  字节1：candidate = 0x34 ⊕ sbox[l]，增加 CK[1][candidate]。  
  字节2：candidate = 0x56 ⊕ sbox[l]，增加 CK[2][candidate]。  
  字节3：candidate = 0x78 ⊕ sbox[l]，增加 CK[3][candidate]。

- 对 Te2（行2）：影响字节 8~11。  
  字节8：candidate = 0x11 ⊕ sbox[l]，增加 CK[8][candidate]。  
  字节9：candidate = 0x22 ⊕ sbox[l]，增加 CK[9][candidate]。  
  字节10：candidate = 0x33 ⊕ sbox[l]，增加 CK[10][candidate]。  
  字节11：candidate = 0x44 ⊕ sbox[l]，增加 CK[11][candidate]。

Te1 和 Te3 命中，不进行排除。

这样一次加密就更新了 8 个字节的计数器（每个字节更新 16 个候选）。

---

## 6. 总结你的疑问

- **数据结构**：16 个数组，每个 256 个计数器。  
- **一次加密排除多个表**：是的，四个表独立，可能同时有多个未命中。  
- **每个表负责一行的四个字节**：Te0→字节0-3，Te1→字节4-7，Te2→字节8-11，Te3→字节12-15。  
- **排除的 16 个候选是针对每个字节独立计算的**：每个字节用自己的密文与 sbox[l] 异或得到候选，并更新该字节的计数器。

## 答疑解惑（2）：

# Flush+Reload攻击破解AES-128加密完整流程详解

Flush+Reload是一种利用CPU缓存时间差异的侧信道攻击，适用于共享内存的场景（如共享库）。攻击者通过监控受害者对特定内存地址（如AES的T表）的访问，推断出密钥信息。下面以AES-128为例，详细说明攻击流程及其核心数据结构。

---

## 一、攻击背景与前提条件

- **目标**：恢复AES-128的最后一轮密钥（即第10轮密钥，记为`K10`）。
- **攻击者能力**：
  1. 与受害者共享CPU缓存（通常通过绑定同一核心实现）。
  2. 能够执行`clflush`指令刷新缓存行。
  3. 能够精确测量内存访问时间（如使用`rdtsc`）。
  4. 知道受害者使用的AES实现细节（如OpenSSL的T表实现），并能够获取密文。
- **受害者行为**：执行AES-128加密，使用基于T表的实现（最后一轮也访问T表，用于提取S盒值）。

---

## 二、核心数据结构

### 1. AES T表（Te0 ~ Te3）
- **作用**：加速AES加密，每个表有256个32位条目（共1024字节）。
- **条目内容**（以OpenSSL为例）：
  ```
  Te0[i] = (2·S[i]) << 24 | (S[i]) << 16 | (S[i]) << 8 | (3·S[i])
  Te1[i] = (3·S[i]) << 24 | (2·S[i]) << 16 | (S[i]) << 8 | (S[i])
  Te2[i] = (S[i]) << 24 | (3·S[i]) << 16 | (2·S[i]) << 8 | (S[i])
  Te3[i] = (S[i]) << 24 | (S[i]) << 16 | (3·S[i]) << 8 | (2·S[i])
  ```
- **最后一轮分工**（基于列优先存储）：
  - AES状态矩阵为4×4字节，按列优先存储：字节索引`pos = row + 4*col`（`row`为行号0~3，`col`为列号0~3）。
  - 输出状态的行与T表对应关系：
    - **Te0** 负责输出状态的第0行（行0），对应密钥字节 **0, 4, 8, 12**
    - **Te1** 负责输出状态的第1行（行1），对应密钥字节 **1, 5, 9, 13**
    - **Te2** 负责输出状态的第2行（行2），对应密钥字节 **2, 6, 10, 14**
    - **Te3** 负责输出状态的第3行（行3），对应密钥字节 **3, 7, 11, 15**

### 2. 监控的缓存行
- **缓存行大小**：64字节，每个T表的前16个条目（索引0~15）恰好占一个缓存行。
- **攻击者监控**：每个T表的这个缓存行（共4个缓存行）。

### 3. 记录数据结构
- **X[i][t]**：二维数组，`i=0..3`表示四个T表，`t`表示第`t`次加密。  
  `X[i][t] = 0`表示本次加密中Te_i的监控缓存行 **未被访问**（缓存未命中）；`X[i][t] = 1`表示被访问（缓存命中）。
- **Ciphertexts[t][16]**：存储每次加密的16字节密文。
- **CK[pos][k]**：16×256的计数器矩阵。`pos`是密钥字节位置（0~15），`k`是候选密钥值（0~255）。  
  `CK[pos][k]`表示在攻击过程中，候选值`k`被排除的次数。

### 4. 辅助数据
- **S盒（sbox[256]）**：公开的AES S盒，用于计算候选密钥。
- **阈值threshold**：通过校准得到的区分缓存命中/未命中的时间值。

---

## 三、攻击流程详解

### 步骤1：准备阶段
- **创建共享内存**：攻击者创建共享内存，在其中生成T表（Te0~Te3），并确保受害者也能访问同一物理内存（通过内存去重或共享库映射）。
- **绑定CPU核心**：攻击者和受害者绑定到同一CPU核心（如核心0），以确保共享L1/L2/L3缓存。
- **建立通信管道**：使用匿名管道实现攻击者与受害者的同步（攻击者发送加密命令，受害者返回密文）。
- **阈值校准**：
  - 测量100次缓存命中时间（先访问目标地址，再测量时间）。
  - 测量100次缓存未命中时间（先`clflush`，再测量时间）。
  - 取中位数，阈值 = (命中中位数 + 未命中中位数) / 2。

### 步骤2：样本收集
对于`t = 0`到所需样本数（如3000）：

1. **Flush（刷新）**：
   - 攻击者执行`clflush`刷新四个T表的监控缓存行（即Te0[0..15]、Te1[0..15]、Te2[0..15]、Te3[0..15]），确保它们在缓存中不存在。
   - 使用`mfence`等指令确保刷新完成。

2. **Encrypt（触发加密）**：
   - 攻击者通过管道向受害者发送命令`'E'`，通知其执行一次加密。
   - 受害者收到命令后，执行一次AES-128加密（使用随机明文），并将密文通过管道返回给攻击者。
   - **注意**：受害者加密时会访问T表，因此如果某次加密中某T表的输入字节落在0~15范围内，对应的缓存行就会被加载到缓存中。

3. **Measure（测量时间）**：
   - 攻击者收到密文后，立即依次测量四个T表监控缓存行的访问时间（使用`rdtsc`等精确计时指令）。
   - 将测量时间与阈值比较：
     - 若时间 < 阈值，判定为缓存命中，记录`X[i][t] = 1`。
     - 若时间 ≥ 阈值，判定为缓存未命中，记录`X[i][t] = 0`。

4. **Record（记录）**：
   - 将本次密文存入`Ciphertexts[t]`。
   - 更新统计信息（如未命中次数）。

### 步骤3：密钥恢复（Algorithm 2）
收集足够样本后，运行Algorithm 2恢复最后一轮密钥`K10`。

**算法输入**：
- `X[0..3][0..N-1]`：缓存访问记录
- `Ciphertexts[0..N-1][16]`：对应密文
- 已知的S盒

**算法步骤**：

1. 初始化计数器`CK[16][256] = 0`。

2. 遍历每个样本`t`：
   - 对于每个T表`i`（0..3）：
     - 如果`X[i][t] == 0`（该表缓存行未命中）：
       - 确定受影响的行`row = i`（因为Te_i负责第i行）。
       - 获取该行四个字节的密文（根据列优先存储，该行字节的位置为`row + 4*j`，`j=0..3`）：
         ```
         c0 = ciphertexts[t][row + 0*4]
         c1 = ciphertexts[t][row + 1*4]
         c2 = ciphertexts[t][row + 2*4]
         c3 = ciphertexts[t][row + 3*4]
         ```
       - 遍历缓存行中的每个索引`l = 0..15`：
         - 计算`s = sbox[l]`。
         - 对于每个列`j`（0..3），计算密钥字节位置`pos = row + 4*j`：
           - 计算候选值`candidate = ciphertexts[t][pos] ^ s`。
           - 将`CK[pos][candidate]`加1（排除一次）。

3. 对每个密钥字节位置`pos`（0..15）：
   - 找出计数器最小的候选值：`best = argmin(CK[pos][k])`。
   - 该`best`即为恢复的密钥字节`K10[pos]`。

### 步骤4：验证
- 将恢复的`K10`与真实密钥（已知测试密钥）对比，计算正确字节数。
- 若全部正确，攻击成功。

---

## 四、攻击原理的精要总结

1. **缓存未命中的信息**：若某T表的监控缓存行未被访问，说明在本次加密中，该表对应的输入字节**不可能**是0~15中的任何一个。
2. **密钥候选排除**：根据加密关系`C = S(x) ⊕ K`，若`x ≠ l`，则`K ≠ C ⊕ S(l)`。因此，每遇到一次缓存未命中，就可以排除16个候选密钥值（每个`l`对应一个）。
3. **统计决策**：正确密钥值永远不会被排除（因为其对应的真实输入字节很少落在0~15内），而错误候选会被反复排除。因此，经过足够样本，正确密钥的排除次数最少，从而被识别。

---

## 五、关键细节与注意事项

- **为什么监控一个缓存行而不是整个表？**  
  因为缓存行是缓存操作的最小单元。监控整个表的16个条目足以推断输入字节是否落在该区间，且减少了需要刷新的地址数量。

- **为什么样本数只需要数千？**  
  因为每次未命中可排除一行上的4个字节，每个字节排除16个候选，即64次排除。AES-128最后一轮未命中概率约7.5%，因此几千样本足以让正确候选脱颖而出。

- **明文随机性**：受害者使用随机明文，保证输入字节均匀分布，使得每个T表输入字节落在0~15的概率约为16/256 = 6.25%，接近理论未命中率（因多轮访问稍有变化）。

- **T表与密钥字节的正确映射**：必须明确Te0影响字节0,4,8,12；Te1影响字节1,5,9,13；Te2影响字节2,6,10,14；Te3影响字节3,7,11,15。这是基于列优先存储和T表行分工得出的。

- **最后一轮T表访问**：虽然最后一轮没有MixColumns，但实现中仍用T表提取S盒值，因此监控缓存行仍然有效。

## 七、总结

Flush+Reload攻击通过精细的缓存监控和统计排除法，能够以极少的样本（约3000次加密）恢复AES-128的最后一轮密钥。其核心创新在于**利用“未访问”信息而非“访问”信息**，从而大幅降低噪声，提高攻击效率。该攻击同样可扩展到AES-192和AES-256（通过EBD攻击），且适用于多种缓存攻击技术（Prime+Probe、Flush+Flush等）。了解此攻击有助于深入理解侧信道威胁和设计更安全的密码实现。
