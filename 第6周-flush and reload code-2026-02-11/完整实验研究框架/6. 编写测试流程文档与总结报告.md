# DES Flush+Reload Attack 测试流程与总结报告

## 一、测试概述

### 1.1 测试目标
验证 DES 加密算法在缓存侧信道攻击（Flush+Reload）下的脆弱性，并评估 7 种缓解措施的实际效果。

### 1.2 测试范围
| 项目 | 内容 |
|------|------|
| **攻击目标** | DES 第一轮 S-box 查找 |
| **攻击方法** | Flush+Reload 缓存侧信道攻击 |
| **测试密钥** | 0x133457799BBCDFF1 |
| **测试轮次** | 25 轮迭代（统计显著） |
| **缓解措施** | 7 种 |

### 1.3 测试环境
```
硬件: Intel i5-1135G7 (Tiger Lake), 2 vCPUs
虚拟化: VMware + Ubuntu 20.04 LTS
内核: Linux 5.15.0-139-generic
```

## 三、测试结果总结

### 3.1 基线攻击结果

| 指标 | 数值 | 说明 |
|------|------|------|
| **攻击成功率** | 84.0% | 25 轮实验中成功恢复密钥的比例 |
| **平均检测 S-box** | 6.7/8 | 每轮平均检测到的 S-box 数量 |
| **SNR** | 10.96 dB | 信噪比，>10dB 表示可区分 |
| **泄露带宽** | 8.56 bits/s | 信息泄露速率 |

### 3.2 缓解措施效果对比

| 缓解措施 | 攻击成功率 | 缓解效果 | 性能开销 | 评估 |
|---------|-----------|---------|---------|------|
| **Baseline** | 84.0% | 0.0% | 0.0% | 基准 |
| **CPU Pinning** | 92.0% | 0.0% | -8.1% | ❌ 无效（负效果） |
| **Cache Flush** | 72.0% | 14.3% | +49.2% | ⚠️ 轻微有效，开销大 |
| **Noise Injection** | 56.0% | **33.3%** | +17.1% | ✅ **有效** |
| **Access Obfuscation** | 56.0% | **33.3%** | +19.0% | ✅ **有效** |
| **Process Isolation** | 84.0% | 0.0% | -8.3% | ❌ 无效 |
| **Core Isolation** | 68.0% | 19.0% | +1.2% | ⚠️ 轻微有效 |
| **Disable HT** | 76.0% | 9.5% | -1.1% | ⚠️ 轻微有效 |

### 3.3 关键发现

#### 发现 1: 软件缓解上限
```
软件缓解措施（Noise Injection, Access Obfuscation）
最大效果: 33.3%
无法完全阻止攻击
原因: 无法解决 LLC 缓存共享问题
```

#### 发现 2: 随机延迟最有效
```
Noise Injection 和 Access Obfuscation 通过随机延迟
破坏攻击者的时间同步，达到 33.3% 缓解效果
性能开销可接受（17-19%）
```

#### 发现 3: 硬件缓解必需
```
软件措施无法解决根本问题（LLC 共享）
需要硬件级缓解: Intel CAT, AMD SEV
```

#### 发现 4: 样本量重要性
```
3 轮实验: 所有措施显示相同效果（33.3%）→ 不可靠
10 轮实验: 效果开始分化
25 轮实验: 效果分布稳定，统计显著
```

## 四、最佳实践建议

### 4.1 生产环境部署

#### 短期措施
```bash
# 1. 禁用 KSM
echo 0 | sudo tee /sys/kernel/mm/ksm/run

# 2. 启用软件缓解（Noise Injection + Access Obfuscation）
```

#### 中期措施
```bash
# 1. 部署 Intel CAT
sudo apt install intel-cmt-cat
sudo pqos -e "llc:1=0x0001;llc:2=0x0002"

# 2. 使用 AES-NI 替代软件实现
# 修改代码使用硬件加密指令
```

#### 长期措施
```
1. 升级到支持 TDX/SEV 的硬件平台
2. 部署专用加密硬件（HSM）
3. 实施零信任架构
```

### 4.2 测试建议

#### 样本量
- 最少 25 轮迭代（统计显著）
- 建议 50-100 轮（更高置信度）

#### 环境控制
- 关闭后台进程
- 固定 CPU 频率（禁用 Turbo Boost）
- 隔离测试环境

#### 结果验证
- 多次重复实验
- 对比不同环境结果
- 理论验证与实际结果一致性
