## 🏛️ 权威来源 3：Meltdown 攻击原理分析

**来源**：[The Microarchitecture Behind Meltdown](https://blog.stuffedcow.net/2018/05/meltdown-microarchitecture/) 

**技术解释**：
Meltdown 发生的微架构条件是：
> "the processor, for a load that fails a permission check, chooses to return a result, **and** that result value is something not normally accessible from user mode"

**硬件修复方式**：从第9代开始，Intel 在 load execution unit 中增加了权限检查逻辑，**在推测执行阶段就阻止对 supervisor-only memory 的访问**，不再返回可使用的结果。

## 📋 关于 VirtualBox 限制的佐证

**关键问题**：VirtualBox 的 `--cpu-profile` 无法改变底层微架构

从技术文档  可知，Meltdown 依赖于**微架构级别的设计选择**（load unit 的行为、乱序执行深度、TLB + Cache 的交互路径）。VirtualBox 的 `cpu-profile` 仅修改 **CPUID**（让操作系统看到假的型号字符串），但**无法模拟旧的 load unit 行为**。
