# 针对DES S盒的Flush+Reload攻击流程详解

## 一、DES加密中S盒的工作方式

在DES的每一轮（共16轮）中，有一步关键操作：**S盒替换**。具体来说：

1. 48位中间数据与48位轮密钥异或
2. 结果分成8组，每组6位
3. 每组6位作为索引，查找对应的S盒表（8个S盒，每个有64个表项）
4. 每个S盒输出4位，总共得到32位

**关键点**：软件实现中，S盒是内存中的查找表。访问哪个表项由以下公式决定：
```
表项索引 = 轮密钥片段 ⊕ 扩展数据片段
```
其中轮密钥片段是攻击者不知道的秘密。

## 二、攻击流程（三步循环）

### 步骤1：Flush（冲刷缓存）

攻击者执行`clflush`指令，强制将S盒表的所有缓存行从CPU缓存中清除，写回内存。

```python
# 伪代码：攻击者清除S盒缓存
for sbox in 8个S盒:
    for entry in 64个表项:
        clflush(sbox_table[sbox][entry])  # 从缓存中清除
```
此时，S盒表完全不在缓存中，任何后续访问都会很慢（需要从内存读取）。

### 步骤2：触发加密

攻击者让受害者程序用DES加密一个**已知明文**。

```python
# 受害者（正常DES加密）
plaintext = 攻击者提供的已知数据
ciphertext = des_encrypt(plaintext, secret_key)  # 这期间会访问S盒表
```

加密过程中，DES算法会根据密钥访问特定的S盒表项，这些表项会被加载到缓存中。

### 步骤3：Reload（重载并计时）

攻击者立即测量访问每个S盒表项所需时间：

```python
访问时间记录 = []
for sbox in 8个S盒:
    for entry in 64个表项:
        start = 高精度计时器()
        value = 读取(sbox_table[sbox][entry])  # 尝试访问
        end = 高精度计时器()
        时间 = end - start
        
        if 时间 < 阈值:  # 比如 < 100周期
            记录: "S盒[sbox]的表项[entry]在缓存中（被访问过）"
        else:
            记录: "S盒[sbox]的表项[entry]不在缓存中（未被访问）"
```

## 三、从访问记录推导密钥

### 已知信息：
1. 攻击者知道明文（自己提供的）
2. 攻击者知道DES算法细节（公开的）
3. 攻击者知道第一轮中每个S盒被访问的具体表项索引

### 推导公式：

对于第i个S盒（i=0..7）：
```
观测到的表项索引 = 扩展后的明文片段 ⊕ 轮密钥片段
```

因此：
```
轮密钥片段 = 观测到的表项索引 ⊕ 扩展后的明文片段
```

### 具体计算示例：

假设：
- 观测到S盒0的表项索引 = 42（二进制101010）
- 扩展后的明文右半部分（E(R0)）前6位 = 011001
- 则轮密钥前6位 = 101010 ⊕ 011001 = 110011

这样，攻击者就得到了第一轮轮密钥的6位。

## 四、重复攻击获取完整密钥

单次加密只能获取8×6=48位信息，但：

1. **第一轮轮密钥**：通过一次加密就能得到48位轮密钥片段
2. **主密钥恢复**：
   - 第一轮轮密钥是56位主密钥经过置换选择2（PC-2）得到的48位
   - 从这48位可以反推出主密钥的48位
   - 剩余8位需要暴力破解（256种可能）
   - 用另一对明文-密文验证即可

3. **提高精度**：由于缓存噪声，通常需要多次加密同一明文，统计哪个表项最常被访问。

## 五、攻击的关键要求

1. **共享内存**：攻击者和受害者必须共享S盒表的内存页
2. **时间精度**：需要高精度计时器（现代CPU的RDTSC指令）
3. **选择明文**：攻击者能控制加密的输入
4. **缓存隔离**：没有硬件级别的缓存隔离

## 六、防御措施

1. **恒定时间实现**：改用位运算而不是查表
2. **掩码S盒**：对S盒输入输出添加随机掩码
3. **缓存清理**：加密前后清理相关缓存
4. **专用指令**：使用AES-NI等专用指令避免软件实现

这个攻击之所以有效，是因为**S盒的访问模式直接泄露了密钥信息**，而缓存的时间差异让攻击者能观察到这种访问模式。
