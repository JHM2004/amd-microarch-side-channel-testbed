# 7.2 虚拟机LLC驱逐攻击详解

---

## 一、VM攻击者的三大困难

**原文**：`Our LLC eviction enables our attack to succeed, but it is using the precise counter and 1 GB paging which are not available to QEMU guests by default.`

**大白话**：我们的攻击需要**精准计时器**和**1GB大页**，但虚拟机默认没有这些。

**困难清单**：

1. **没精准计时器**：`rdtsc`被虚拟化，误差±100ns，分不清命中/未命中
2. **没1GB大页**：云厂商只给2MB大页，1GB页要特权
3. **构造太慢**：暴力搜索地址太慢，还容易出噪

---

## 二、解决方案1：集体测量（信号放大）

**原文**：`measuring the access times of all entries in an eviction set together rather than separately to amplify the signal`

**核心思想**：**不测单个地址，测整个驱逐集的总时间**

```c
// ❌ 旧方法：一个一个测（慢+不准）
for each addr in eviction_set:
    t = reload(addr)  // 噪声大，分不清

// ✅ 新方法：一起测（快+准）
start = rdtsc()
for each addr in eviction_set:  // 循环2047次
    access(addr)                // 只访问，不测时间
end = rdtsc()

total_time = end - start
// total_time小 → 全命中；total_time大 → 有未命中
```

**效果**：信号放大**3倍**，噪声抵消

## 三、解决方案2：XOR函数快速合并

**原文**：`efficient eviction set generation approach without relying on 1GB huge pages`

**核心突破**：**用XOR索引函数跨页合并L2集**

### 3.1 XOR函数的神奇

AMD的L2和LLC用**XOR**算组索引：

```
d = a ⊕ b ⊕ c
```

**含义**：如果L2集a和L2集b在LLC冲突，那么L2集d = a XOR b XOR c 也冲突。

**优势**：
- **测试次数**：63,364次 → **16次**
- **成功率**：60% → **100%**（原文O10）
- **耗时**：10分钟 → **30秒**

## 四、完整三步流程

### **Step 1：提取L2集（单个大页）**

```c
// 在2MB大页内，提取2047个地址
// 这些地址填满L2的4个组
l2_set = extract_l2_from_hugepage(page_base);
```

### **Step 2：跨页合并（31个大页）**

```c
// 对每个大页，用XOR函数算LLC冲突
for (int j = 1; j < 31; j++) {
    // 只需测试1个地址，算出冲突集
    int colliding_set = xor_calculate(l2_set[0], l2_set_j[0]);
    
    // 其他2046个地址直接合并，不用测
    merge_all(l2_set, l2_set_j, colliding_set);
}
```

### **Step 3：Prime+Probe攻击**

```c
// Prime：用合并后的驱逐集填满LLC Set S
prime(llc_eviction_set);

// 等待受害者VM1访问密钥（也在Set S）

// Probe：集体测量，看哪路被驱逐
if (probe(llc_eviction_set) > THRESHOLD) {
    leak_success();
}
```
